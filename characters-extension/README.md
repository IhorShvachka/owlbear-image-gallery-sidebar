# Персонажі — окреме розширення Owlbear Rodeo

Цей каталог є ізольованим проєктом у гілці `feature/characters-extension`. Він не змінює файли Image Gallery і не розгортається замість неї.

## Призначення

- Майстер вибирає токен на активній карті й призначає його конкретному гравцеві в даних шаблону.
- Майстер може створити нову копію шаблону на активній сцені; вона додається в центр поточного перегляду.
- Створюється канонічний шаблон персонажа з унікальним ID.
- Зміни підтримуваних властивостей синхронізуються між позначеними копіями на активній сцені; інші сцени узгоджуються лише після їх активації.
- Координати/позиція кожної копії є локальними й ніколи не переносяться в шаблон.
- Гравець має керувати тільки призначеним йому персонажем; майстер може керувати всіма.

## Важливі технічні умови

1. Дані шаблонів зберігаються в метаданих кімнати, а не лише в локальному сховищі браузера.
2. Кожна копія токена позначається власними метаданими розширення з `characterId`.
3. Під час синхронізації копій застосовуються властивості шаблону, крім позиції, повороту й масштабу. Ці трансформації лишаються локальними для кожної копії.
4. Оновлення, зроблені самим синхронізатором, мають відрізнятися від ручних змін, щоб уникнути циклів.
5. Код синхронізує позначені копії активної сцени та повторно узгоджує їх зі збереженим шаблоном, коли сцена стає активною або змінюються метадані кімнати. Він не може негайно змінити копії на неактивних сценах; їхнє узгодження відбувається після відкриття відповідної сцени.
6. Обмеження контролю токенів треба перевіряти на стороні логіки розширення та тестувати в кімнаті з кількома підключеними користувачами. Приховування кнопок саме по собі не є дозволами.

## Межі поточної синхронізації

Синхронізатор переносить лише визначений набір полів: назву, видимість, блокування, порядок відображення, опис, параметри зображення/сітки та текст зображення. Він навмисно не копіює ID, власника-автора, шар, метадані розширень, позицію, поворот або масштаб. Це зменшує ризик випадково перезаписати системні поля Owlbear. Інші типи властивостей поки не підтримуються.

Під час призначення власника розширення записує ID вибраного гравця в `createdUserId` токена, а під час створення копії — у новий елемент. Це використовує поле, яке підтримує SDK, але реальна поведінка власності має бути перевірена в Owlbear. Для обмеження керування гравцями окремо ввімкни **Character → Owner Only** у дозволах кімнати. Документація: [Items API](https://docs.owlbear.rodeo/extensions/apis/scene/items/), [Item fields](https://docs.owlbear.rodeo/extensions/reference/items/item/), [Permissions](https://docs.owlbear.rodeo/docs/permissions/).

## Поточний стан

Є початковий UI, вибір власника зі списку учасників кімнати, збереження шаблонів у метаданих кімнати, створення копій на активній сцені, синхронізація копій активної сцени та узгодження при активації сцени. Додано окремий workflow для збірки в GitHub Actions, але його успішний запуск ще не підтверджено. Це все ще не готова версія для встановлення. Перш ніж оголошувати функціонал готовим, потрібно реалізувати й перевірити SDK-поведінку на різних сценах та з кількома гравцями.
