# Персонажі — окреме розширення Owlbear Rodeo

Цей каталог є ізольованим проєктом у гілці `feature/characters-extension`. Він не змінює файли Image Gallery і не розгортається замість неї.

## Призначення

- Майстер вибирає токен на активній карті й призначає його конкретному гравцеві.
- Створюється канонічний шаблон персонажа з унікальним ID.
- Зміни властивостей синхронізуються між усіма копіями персонажа на різних сценах.
- Координати/позиція кожної копії є локальними й ніколи не переносяться в шаблон.
- Гравець має керувати тільки призначеним йому персонажем; майстер може керувати всіма.

## Важливі технічні умови

1. Дані шаблонів зберігаються в метаданих кімнати, а не лише в локальному сховищі браузера.
2. Кожна копія токена позначається власними метаданими розширення з `characterId`.
3. Під час синхронізації копій застосовуються властивості шаблону, крім позиції, повороту й масштабу. Ці трансформації лишаються локальними для кожної копії.
4. Оновлення, зроблені самим синхронізатором, мають відрізнятися від ручних змін, щоб уникнути циклів.
5. Код синхронізує позначені копії активної сцени та повторно узгоджує їх зі збереженим шаблоном, коли сцена стає активною або змінюються метадані кімнати. Він не може негайно змінити копії на неактивних сценах; їхнє узгодження відбувається після відкриття відповідної сцени.
6. Обмеження контролю токенів треба перевіряти на стороні логіки розширення та тестувати в кімнаті з кількома підключеними користувачами. Приховування кнопок саме по собі не є дозволами.

## Етапи реалізації

- [x] Ізольована гілка та документація вимог.
- [x] UI для вибору токена на сцені та призначення гравцеві зі списку учасників кімнати.
- [ ] Канонічна модель персонажа й збереження в room metadata.
- [x] Початкове відстеження властивостей і синхронізація позначених копій у межах активної сцени (потрібне тестування).\n- [x] Початкове узгодження позначених копій зі шаблоном при активації сцени (потребує перевірки в Owlbear Rodeo).
- [ ] Миттєва синхронізація копій на неактивних сценах (може потребувати іншої архітектури).
- [ ] Призначені права гравців і захист від редагування чужих токенів.
- [x] Додано окремий GitHub Actions workflow для перевірки збірки гілки розширення (результат запуску ще не підтверджено).
- [ ] Успішна збірка й тест у реальній кімнаті Owlbear.

## Поточний стан

Є початковий UI, вибір власника зі списку учасників кімнати, збереження шаблонів у метаданих кімнати, синхронізація копій активної сцени та узгодження при активації сцени. Додано окремий workflow для збірки в GitHub Actions, але його успішний запуск ще не підтверджено. Це все ще не готова версія для встановлення. Перш ніж оголошувати функціонал готовим, потрібно реалізувати й перевірити SDK-поведінку на різних сценах та з кількома гравцями.
